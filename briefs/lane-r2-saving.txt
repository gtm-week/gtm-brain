Design choices already settled for this round (apply the ones for your lane):
- R1: the one-call mode is a new derived object of the existing query tool named "answer" (query {object: "answer", search: "<the question as asked>"}); the plain memories search path gets the same engine (stemming, typo tolerance, ranking, cap). Bump the index version and switch the full-text table to a stemming tokenizer; a rebuild on first use after upgrade is fine, measure it. Typo tolerance by edit distance 1 on words of five or more letters from the index vocabulary, ranked below exact matches, with one line saying what was searched instead. The cap is a constant default of about 12 KB plus the existing limit argument; no new setting file. No synonym map: handle hyphens and plurals through stemming, and weekday or month words as periods.
- R2: look for duplicates across the whole brain, not one topic. A restatement whose values are a subset of a kept note is "already kept" and writes nothing; a differing value of the same type supersedes the matched note automatically and says so.
