## Lane S5: the nightly capture pass
The brain misses outcomes that were said in a chat and never saved. A background run exists (scripts/gtm-brain-schedule, the launchd or scheduled job set up by the schedule script, GTM_BRAIN_RUN, the compile toolset; see how sessions and chats are found in lib/host.mjs currentChat and the host's session files).
Owner's decisions: the pass runs on the laptop in the existing background run; if the laptop was closed at night it catches up at the next chat start; the chat start shows one line when the last pass is older than 36 hours; it reads only chats changed since the last pass and stops near 200,000 tokens, saying what it skipped; it can be switched off.
Build:
- A capture pass: find the host chats in this brain's folder (and linked project folders) changed since the last pass; for each, extract the person's and the assistant's turns compactly (no tool output, no file dumps), skip chats already fully covered, and hand them to one bounded model run whose only job is to list outcomes that were established and not saved (decisions, changes, commitments with dates, corrections), each as a candidate note with the exact sentence it rests on and the chat it came from.
- Candidates are saved through the normal remember path, tagged captured with the chat as source, so every rule and check applies (duplicates are refused there). They are listed in one line at the next chat start ("3 notes captured from yesterday's chats: ... Say 'undo captured' to withdraw them"), and can be withdrawn together.
- Budget: a hard cap on input tokens per pass (default 200,000) and per chat; when the cap is reached the pass stops, records what it skipped, and continues next time from there. Report the tokens of each pass in its record.
- A heartbeat: the time, result and token count of the last pass in the brain's machine-local state; the health line shows one line when the last successful pass is older than 36 hours or the last one failed, with the reason in the person's terms. A pass that cannot run (not signed in, the host's state database read-only, the model tool unavailable) records that reason. Those exact failures happened on a real machine for weeks without anyone being told.
- Catch-up: at chat start, if the last pass is older than 36 hours, offer to run it now in one line (do not run it silently inside a person's turn).
- A setting to turn it off, and to change the cap.
- It must never read another brain's chats, never read chats outside the brain and its linked folders, and never send anything anywhere but the model run it starts.
