# GTM Brain: What's next

Keep authored brain content in English. Preserve names, source quotes and the exact approval token `APPROVE`.

> For humans: concrete next steps backed by the context's notes and relevant current sources.
> Nothing is written.

## Steps

1. `query` (status); if a context is named, `load_context` it (`mode: add`). If nothing is open,
   infer relevant existing contexts from the request. Only when there is no task to infer from,
   ask what the person wants to work on using `question` and concrete business choices.
2. Read [operational evidence](../../gtm-brain-use-brain/references/operational-evidence.md).
   For each open context, use the summary, open questions and follow-up memories as candidates.
   Working guidance explains reusable methods; it is not a list of pending tasks. Older
   guidance can contain next steps, but those need support from current effective memories.
   Check the memories behind material next steps and, when their status depends on an external
   tool, make a targeted read there. If access is unavailable, label the status as last recorded
   with its date. Honor requests to use recorded knowledge only.
3. Answer in this shape, per context, five lines at most:

    **Pipeline.** Next: <specific action on a named account or item, with evidence and why now>.
    Pending: <verified owner and date, or explicitly unknown>. New: <what the newer notes or
    checked source changed>. Link supporting records or cite the context and memory date.

4. Use newer evidence even while the summary updates in the background. Do not make summary
   maintenance a prerequisite to answering. If the person wants to act on an item, hand over
   to `gtm-brain-todo`.

## Hard rules

- Facts trace to memories or checked sources; recommendations are identified as proposals.
- An old open question is not evidence that the external work is still pending.
- Nothing is recorded by this skill.
