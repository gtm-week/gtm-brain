# GTM Brain: Add a reusable section

By Brian Woloszczak and Peakout. Read [the method](references/method.md) once and follow it.
Conduct the conversation and author brain records in English. Preserve names, source quotes
and the exact token `APPROVE`.

## 1. Reuse what the brain knows

Reuse the session's resolved person and company. Resolve the shared website through
[the project flow](../gtm-brain-design-system/references/project.md). If no website project
exists or its design system is not set up, run
[Build our design system](../gtm-brain-design-system/SKILL.md) first, then come back.

Read `design-system.md` and, for copy, `voice.md` with `document` (`action: show`). Reuse the
source URL and section heading the person gave, or the brief for a new section.

## 2. Run Brian's procedure in the project

From the project folder, read `docs/workflows/add-section/SKILL.md` in full and follow it:
component composition, the typed registry, documentation and verification.

## 3. Ask, one question at a time

Follow [question handling](../gtm-brain-start/references/questions.md). Ask only for missing
content, behaviour and business decisions. A calculator's formulas belong in its brief; ask
for them, never guess.

## 4. Keep the result

The section lives in the project's registry, for every campaign, not only the current page.
Nothing goes into the brain unless the person states a decision worth keeping; then follow the
[remember procedure](../gtm-brain-use-brain/references/remember.md).

Finish in one to three sentences: the local catalogue preview, the interaction checks and the
results at all three widths, plus missing copy or unconnected services. When a shared
component changed, say which existing pages you rechecked.

## Boundaries

Never publishes: remote publication is [Publish the website](../gtm-brain-publish-website/SKILL.md),
on its own request. Never invents claims, quotes or numbers for the section's copy.
