# Collection and evidence contract

Use this contract for topic analysis and audience discovery. Read the source through its
available MCP connector first; supplied exports and existing dated notes are valid inputs.
Use an authorized API when appropriate. Follow the project's tool and browser-access policy.

Before new paid work, verify current provider schema, pricing and maximum full-request cost.
Apply the company's explicit request, run, daily and cumulative caps, including outstanding
reservations. No budget is supplied by this reusable skill. Missing authority blocks paid work,
not analysis of already available evidence. Never copy credentials into research artifacts.

Use an existing resumable collector when one is available. Record a stable request identity,
intent and maximum-cost reservation before launch. Reconcile an uncertain request through the
provider before retrying; retain its reservation while unknown. Never split requests to bypass
approval limits. If no collector can preserve these guarantees, stop before paid launch and
report that prerequisite rather than improvising a bulk collector.

Keep minimal evidence: source URL or provider ID, author/speaker and original authorship,
event date separately from retrieval date, relevant excerpt or summary, selected profile,
coverage/pagination, and collection reference. Preserve factual observations separately from
inferences and review decisions. Never manufacture a source URL or an unknown event date.

Cite the file or record actually read. A prepared export may summarize and reference another
source; attribute those claims to the export and mark the original as unread if it is not
available. Do not turn its reference into a direct-read citation. Use exact source IDs or
existing paths, never abbreviated or reconstructed links.

Raw payloads and temporary caches stay in the source system or designated project storage,
with its retention rules. Durable conclusions keep source pointers before cache expiry;
expired data is not fresh evidence. Preserve partial coverage explicitly. Missing rows in a
partial result do not prove removal, inactivity, rejected invitations or changed relationships.
