Where things go, first match wins: workplace info (company, team, tools) is `brain/admin.md`
(rule 3); a standing document the work must follow (strategy, voice, design system, ICP
definition, pricing, a surface's writing standard) is a document (rule 11); a person,
organization or product is an entity (rule 2a); a file is landed beside its owner and, for an
entity, attached; everything that happened, was decided, found or asked is a memory in the
context whose purpose fits (rules 1 and 2). A strategic choice is a memory in Strategy as well
as a line in the strategy document; the document is the statement, the notes are the evidence.
A document a chat or a skill produces (a strategy, a plan) is written as a document through
`document`, at the root or in the folder the person names; its decisions and findings also
become memories, and a draft in progress lives in the project folder it belongs to. Never leave
it as a loose Markdown without the marker, and never invent a folder such as `company/` or
`assets/` beside `brain/`.

`RULES.md` at the brain root decides where every file goes, and the person edits it: put each
file where a row says and name the row in one short clause. The opening lines carry its rows and
the projects under `projects/`. Work built for a goal (a deck, graphics, a page, an export, a
batch of downloads) goes inside its project, `projects/<project>/<deliverable>/`: a task that
belongs to a listed project goes in that project, never in a folder of its own. With no fitting
project or row, ask before creating a folder, and offer a new row. After creating, editing,
moving or deleting files in the brain yourself (a graphic, a brief, `RULES.md`), call `save` once
when the task is done, so the team gets them. Never put a deliverable in `work/` or a new folder
at the brain root. Only what is worth keeping from a raw source becomes a document or notes. A
playbook is a workflow (gtmb-workflow): steps that play out over time, started and tracked
as a run. Why a file is where it is: `query` with object why and `search` = the path.

**Entity attachments.** A file the person hands over goes through gtmb-use-brain's
references/files.md: it lands beside its owner (a document's files folder, or the entity's own
folder for a person, company or product; a file with no owner is refused, so ask what it belongs
to; a project file stays in its project folder), an entity file is attached through `remember`
with `asset`, and its content is noted. The opening lines name the approved files (a person's
photo, a company's logo). Use exactly those for a graphic, page or deck; ask if several match or
only drafts exist. A file the person approves for a person, company or product ("this is my
photo", "this is our logo", "use this one instead") is kept only by `keep_approved_file`, in the
same turn; never say it is saved without that call. Never delete the source file.
