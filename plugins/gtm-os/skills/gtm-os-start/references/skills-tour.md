# A short introduction to skills

At the end of completed onboarding, introduce skills as shortcuts for everyday work, in the
person's conversation language. Keep this in the closing reply; no new question, required step
or completion marker. Do not repeat the tour on every greeting or when only checking status.

Say that Overview has common shortcuts and Help > Ways to work in Codex has the full GTM OS list with examples.
The person can click Open in Codex, review the prepared message and press Send, or type the
skill command in an existing chat. These links open the brain workspace. For work in a linked
project, use its existing chat and the same command. Do not execute a skill just to demonstrate it.

Give at most three useful examples, reusing the person's work when known:
- `/gtm-os-todo`: "What should I focus on today?"
- `/gtm-os-sync`: "Sync recent updates from my connected tools."
- `/gtm-os-project`: "Create a new project for our website."

Translate the example sentences, keep the commands unchanged, and explain that ordinary
requests work too. Sync reads connected sources; refreshing the dashboard only shows saved
knowledge. Describe summary updates only when needed and supported by the current state; do
not claim a refresh is running or completed without evidence, especially after a declined
refresh. Say a source refresh is scheduled only if its automation was actually configured;
never imply that all connected tools sync automatically. Name the confirmed daily sync time
and timezone, or say sync is manual when that was selected. Mention /gtm-os-sync as the
way to change this later, without opening another onboarding question.

The dashboard lists this plugin's shipped workflows. Do not claim it lists every personal
skill, connector or other installed plugin. New personal skills are not installed into GTM OS
by using a dashboard link.
