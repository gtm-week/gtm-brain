# Topic and audience research

| Skill | Result |
| --- | --- |
| `/gtmb-topic-analyzer` | Sourced topic priorities from any supplied ICP list, interviews, CRM notes or post evidence |
| `/gtmb-audience-loop` | Independently assessed ICP candidates, conversation hosts and useful discussion openings |

Each skill works alone. Topic analysis owns scoped evidence collection for its input list;
it does not require Audience Loop admission or history. A handoff carries source references,
profile, dates and unresolved questions, never qualification or approval.

Read the selected offering and evidence first. Separate facts, inferred fit, recommendations
and review decisions. Broad topic research can retain material that is unsuitable for a live
contribution. Both skills share the contribution-filtering contract when proposing angles or
conversations. A source link, engagement count or completed step does not prove relevance.

For a short LinkedIn session, check discussion access before setup questions. Lead with one
verified opening or explain the specific evidence gap. Unpublished drafts are not live posts.
Buyer fit and conversation-host qualification require independent evidence; list admission
remains separate. Existing customers or excluded outbound accounts can still inform research
when the exclusion's scope permits it.

## Storage and continuation

Reports use the document tool or an established project destination. Supported findings and
actual feedback use sourced memories in an existing context. Reuse entity IDs and record shown
threads with their profile, branch and review time. Preserve exact corrections and their scope.

Topic analysis and Audience discovery ship as manual draft workflow templates. They use the
existing engine: save a sourced, run-scoped finding or actual review response, verify it, then
advance the matching note milestone. The skill checks the evidence; this change does not add
engine-enforced source validation or new MCP operations. Setup copies the templates to new
brains. Upgrade leaves an existing workflows folder alone; adoption there uses normal workflow
creation. Neither installing nor saving a template activates or schedules it.

## Development and evaluation

Portable methods are developed independently in LinkedIn Agent and shipped here as self-contained
files. `research-source.json` records the source revision and content hashes. There is no runtime
dependency on that repository or Python. Changes can be reviewed and maintained in this checkout.

The [evaluation](../plugins/gtm-brain/test/research/README.md) uses the pinned Berlin mock dataset
and the existing real-Codex harness. Its cases cover topic independence, contradictory timing,
unknown authority, identity ambiguity, exclusions, missing live evidence and saved findings.
Expected answers stay outside the evaluated workspace. See the accompanying evaluation report
for measured outcomes and limits; the files do not contain LinkedIn discussion threads.

Provider access, budgets, tracking rules, delivery and retention belong to each company.
No collector, paid allowance, delivery destination, global installation or external engagement
is introduced by these skills.
